# تنفيذ التكليف على مشروع MotoShop

## 1) تطبيق مفاهيم المحاضرات
تم ربط مفاهيم المحاضرتين 6 و7 بالمشروع عملياً:

- **رفع الملفات والصور**: المشروع يستخدم `ImageField` للصور، و`request.FILES` لتعديل الصورة الشخصية، وتمت إضافة تحقق من نوع وحجم الصورة (JPG/PNG/WEBP وبحد أقصى 2MB).
- **Signals**: تمت إضافة Signal ينشئ `UserProfile` تلقائياً لأي مستخدم، وSignal لتأكيد الطلب عبر البريد الإلكتروني عند إنشاء Order.
- **Middleware**: تمت إضافة Middleware خاص بصفحات الضيوف لمنع المستخدم المسجل من الوصول إلى login/register.
- **Email**: تم ربط إنشاء الطلب برسالة تأكيد بريد إلكتروني باستخدام إعدادات SMTP الحالية، مع `fail_silently=True` حتى لا يتعطل الطلب عند غياب إعداد البريد أثناء التطوير.
- **Messages / Notifications**: المشروع يستخدم Django Messages لإظهار رسائل النجاح والتحذير للمستخدم بعد العمليات المختلفة.
- **QuerySets والعلاقات**: أبقيت تطبيق One-to-One وMany-to-Many وQuerySet Lab الموجود بالمشروع كما هو لأنه يحقق مفاهيم سابقة بالفعل.

## 2) ثيم Django Admin
تم اختيار **Django Grappelli 4.0.4** بما يناسب Django 5.x، مع إعداد fallback للـ admin الافتراضي قبل تثبيت dependencies.

## 3) منع دخول login/register للمستخدم المسجل
تم تنفيذ الحماية من خلال Middleware مركزي؛ لذلك سواء ضغط المستخدم رابط الصفحة أو كتب `/account/login/` أو `/account/register/` يدوياً في شريط العنوان، يتم تحويله إلى `home` إذا كان مسجل الدخول.
